# 系统架构

```text
浏览器页面（诊断工作台 / 服务工单台 / 知识库 / 诊断 Skill / 用户管理 / 客户服务门户）
-> FastAPI 后端
   -> 诊断编排（检索 + 工具 + 结构化结论）
   -> 模型网关（模型提供方可配置）
   -> 混合检索（词法 + BGE-M3 向量）
   -> 保修与到场判定
   -> Skill 约束加载
   -> MCP 工具网关（stdio JSON-RPC）
-> 关系库（SQLite / PostgreSQL + pgvector）
-> 本地文件与诊断数据集
```

## 诊断数据流

```text
客户描述
-> 识别设备（编号 / 出厂编号 / 工单号 / 手动选择）
-> 读设备档案、保修合同与实时数据（MCP 工具）
-> 检索故障树、服务通报与历史工单
-> 选出最可能的故障（文本匹配 + 检索章节 + 相似工单投票）
-> 结构化诊断：故障ID / 原因 / 处置 / 手册章节 / 是否到场 / 备件 / 保修
-> 信息不足时给出追问问题
-> 模型组织为自然语言回答，附引用
```

## 工单流转

系统以**服务工单**为工作单位，诊断结论挂在工单下：

```text
接客户来电 -> 登记工单（客户 / 设备 / 来源 / 优先级 / 现象）
-> 在诊断工作台关联该工单发起诊断
-> 结论、派工建议、对客户话术、内部备注回写工单
-> 状态推进：待研判 -> 待派工 -> 已派工 -> 已关闭
```

## 信息分层

诊断输出分两层，避免把内部信息发给客户：

| 层次 | 内容 | 可见范围 |
| --- | --- | --- |
| 内部 | 故障 ID、置信度、风险提示、结算方式、备件物料号与成本、服务通报编号、二线复核建议 | 内部角色 |
| 对外 | 现象复述、初步判断、手册依据、建议处理、到场安排、免责说明 | 可一键复制发给客户；客户门户仅显示这一层 |

## 组件职责

| 组件 | 职责 |
| --- | --- |
| `routers/` | HTTP 接口与页面路由 |
| `services/diagnosis.py` | 诊断编排：选故障、组合结论、生成追问 |
| `services/service_request.py` | 服务工单编号、生命周期与诊断结论回写 |
| `services/dispatch.py` | 派工建议与对外话术，内部信息与对外内容严格分开 |
| `services/warranty.py` | 保修状态与结算方式判定 |
| `services/mcp_gateway.py` | MCP stdio 客户端，隔离工具进程 |
| `services/model_gateway.py` | 统一模型调用与提示词组装 |
| `services/retrieval*.py` | 词法/混合检索与向量后端分派 |
| `services/seed.py` | 从诊断数据集导入主数据与知识切片 |
| `remotediag/mcp_server.py` | 只读工具服务，读取诊断数据集 |

## 当前边界

- 诊断数据集与 MCP 服务独立于产品后端，通过进程与配置连接，不内嵌。
- 工具全部只读；诊断结论以建议形式给出，写操作不落地。
- Skill 为声明式配置，不执行上传代码。
- 诊断是内部客服能力；客户账号只能只读查询本企业设备与服务记录。
- 开发用 SQLite，现场可切 PostgreSQL + pgvector，切换只改配置。
- 无实时数据时走工单与故障树路径，系统会明确说明数据缺口。
