# 系统使用说明

面向客服中心与知识库维护人员。文中的界面名称与操作路径对应线上版本。

---

## 1. 一句话说明

接到客户报修后，先登记一张**服务工单**，在工单里发起一次诊断；系统读出这台设备的
档案、保修、实时数据，检索手册、服务通报和历史工单，给出**故障判断、是否需要到场、
预计工时、建议备件、是否收费**，并把结论写回工单。客服确认后，把"对客户说明"发给客户。

---

## 2. 谁用它

| 角色 | 账号示例 | 能看到什么、能做什么 |
| --- | --- | --- |
| 客服工程师 | `agent01` | 服务工单台、诊断工作台。登记工单、发起诊断、推进工单状态 |
| 技术支持工程师 | `tech01` | 目前与客服相同（二线复核界面尚在开发） |
| 知识库管理员 | 由管理员创建 | 额外可进「知识库与资料」「诊断 Skill」，上传与发布资料 |
| 服务主管 | 由管理员创建 | 额外可看服务质量指标与诊断评测结果 |
| 系统管理员 | `admin` | 全部权限，另可管理用户、重置密码、停用账号、查看审计日志 |
| 客户联系人 | `cust01` | 只读门户：本企业设备档案与保修、服务记录与处理反馈，不能发起诊断 |

账号由系统管理员在「用户管理」中创建；客户联系人账号必须绑定到某个客户，
登录后只能看到该客户自己的设备和工单。

## 3. 一次工单的完整流程

```text
① 接电话        客户说清现象
② 登记工单      客户 / 设备 / 来源 / 优先级 / 现象    （约 30 秒）
③ 发起诊断      点「去诊断」，工作台已自动关联该工单
④ 读结论        故障、是否到场、预计工时、备件、是否收费
⑤ 补问（按需）  结论下方「建议追问」列出要问客户的问题，问完再研判一轮
⑥ 回复客户      复制「对客户说明」，直接发给客户或口头转述
⑦ 推进工单      回工单台标记「已派工」或「关闭」
```

### 第 ② 步：登记工单

进入「服务工单」，左侧 01 区填四项：**客户**（下拉，选完设备列表自动跟着过滤）、
**设备**、**来源**（电话/平台/邮件/现场）、**优先级**（紧急/高/普通），
再把客户说的现象照原话写进"现象描述"。点「创建工单」，系统自动给出工单号，
格式形如 `SR-2026-0001`，状态为「待研判」。

### 第 ③ 步：发起诊断

工单创建后点「去诊断」跳到诊断工作台，工单已经关联好（顶栏显示工单号）。
左侧「我的工单」也能随时切换工单。把客户描述填进底部输入框，点「发起诊断」。

也可以不建工单直接诊断——这种情况下结论不会写回任何工单，适合快速验证或口头咨询。

### 第 ④ 步：读结论

诊断过程中顶部有四步进度：**读取设备与保修 → 查询实时报警 → 检索手册与通报 →
生成诊断结论**，每步完成打勾，不用盯着屏幕猜它卡在哪。

右侧固定四张卡片，从上到下依次是结论、派工建议、内部备注、对客户说明。
字段含义见第 5 节。

### 第 ⑥ 步：回复客户

「对客户说明」是已经写好的一段话，点「复制」即可粘到微信、工单系统或口头转述。
这段话只包含客户该知道的内容——现象复述、初步判断、手册依据、建议处理、到场安排，
**不含**备件物料号、库存成本、结算口径和内部通报编号。

## 4. 界面导览

### 4.1 诊断工作台（主界面）

三块区域：

- **左侧栏**：导航 + 「我的工单」队列。队列按工单号列出，带状态色标，
  并直接显示初判结论（例如"F03 液压油温过高 · 建议到场"），扫一眼就知道哪张单该先处理。
- **中间**：与客户的这一轮对话。上半是客户口述，下半是诊断助手的结论叙述，
  以及需要向客户补充确认的问题。
- **右侧**：结论与输出。诊断结论、派工建议、内部备注（黄色底，标"仅内部 · 勿外发"）、
  对客户说明、依据引用。切换工单时会自动带出该工单上次的结论，不用重复诊断。

### 4.2 服务工单台

01 区登记新来电，02 区按状态筛选工单列表，03 区是工单详情：
客户与设备信息、现象描述、派工建议、内部备注、对客户说明、依据引用，
右下角可把工单标记为「已派工」或「关闭」（关闭时可留一句备注）。

### 4.3 知识库与资料

上传故障树、手册、服务通报后，系统自动解析并切片，进入**预览**状态——
此时不会影响诊断检索；确认切片没问题再点「发布」，之后才会被检索到。

切片方式可选四种：按标点、按段落、按标题、按固定长度。上传时可调最大长度与重叠长度。
支持 TXT、Markdown、DOCX 和**文字版** PDF；扫描版 PDF 会提示需要 OCR，
装了 OCR 环境后可识别并逐页人工校对。

### 4.4 诊断 Skill

声明式的诊断技能配置（JSON / Markdown / 含 `skill.json` 的 ZIP）。
它只约束"用哪些资料范围、按什么模板回答"，**不执行任何上传的代码**。
发布后可在工作台右上角手动指定，也可让系统按问题自动匹配。

### 4.5 客户服务门户

客户账号登录后进入的只读页面：本企业在用设备的档案与保修状态，
以及提交过的服务记录和处理反馈（就是客服复制给他们的那段"对客户说明"）。
客户看不到诊断过程、内部备注和商业信息。

## 5. 诊断结论怎么读

| 字段 | 含义 | 怎么用 |
| --- | --- | --- |
| 故障 ID + 名称 | 如 `F03 液压油温过高` | 对内部沟通用编号，对客户只说名称 |
| 置信度 | 高 / 中 / 低 | **高**可直接采纳；**中**建议先做"建议追问"里的补充确认；**低**或显示"待确认"不要回复客户 |
| 需到场 / 远程可处理 | 处理方式 | 决定排不排工 |
| 手册章节 | 如 `4.2.1` | 工程师的作业依据，可直接翻手册 |
| 典型原因 | 最可能的根因 | 用于预判备件与作业时间 |
| 处置要点 | 复位或处置动作 | 远程指导客户时可照此口述 |
| 结算方式 | 保修内免费 / 批次性通报按通报免费处理 / 已过保需报价 | **对客户报价前必须先看这一项** |
| 服务等级 | 如 `SLA-A 4h 响应 / 24h 到场` | 承诺时限的依据 |
| 派工建议 | 处理方式、判定依据、预计工时、工时依据、建议备件 | 排工与备件的依据 |
| 建议二线复核 | 出现时表示结论不够硬 | 先找二线确认再回复客户 |
| 内部备注 | 风险提示、结算、备件明细、命中的服务通报、待补信息 | **仅内部可见，不要发给客户** |
| 依据引用 | 手册章节、历史工单号 | 客户质疑时可回溯 |

**预计工时不是估的**：系统统计同类故障的历史工单实际耗时，例如
"1.1–2.6 小时，同类历史工单 4 条，平均 1.9 小时"。

## 6. 几种常见情况

**结论显示"置信 中"并列出"建议追问"**
说明关键信息不够。按列出的问题问客户（例如"冷却水进出水温差多少？油温是运行几小时后
才升还是开机就偏高？"），把回答补进去再研判一轮，结论会收敛。

**提示没有实时数据**
这台设备可能没联网或平台掉线。系统会明确说明"数据缺失期间无法远程监视"，
并给出需要现场确认的事项——这种情况不要凭空下结论。

**命中服务通报**
说明是已知的批次性问题。内部备注里会给通报编号和处理口径；
对客户说明里只会体现处理安排，不会出现内部编号。若工单已过保但命中通报，
结算方式会自动变成"按通报免费处理"。

**建议二线复核**
出现在置信度不足、严重度高的故障、或命中服务通报三种情况。
此时结论只能作为内部参考，回复客户前先走二线。

**诊断要等 5–10 秒**
系统在依次读设备档案、查报警、检索手册与历史工单，最后生成结论。
顶部进度条会显示当前进行到哪一步。

## 7. 管理侧日常维护

- **资料更新**：手册换版或新增服务通报后，在「知识库与资料」上传新文件并发布；
  旧版本可停用或删除。故障树更新后建议重跑一次诊断评测看指标是否下降。
- **账号**：新同事入职在「用户管理」创建账号并分配角色；离职或调岗及时停用。
  停用会立即失效该账号的登录会话。
- **审计**：系统记录每一次诊断、每一次模型调用、每一次工具调用和管理操作，
  可按时间倒序查询，用于复盘争议工单。日志里保存工具调用参数与结果。
- **质量指标**：管理侧可查看诊断总量、完成量、追问率、建议到场的比例、
  模型平均耗时，以及内置评测集的诊断准确率。

## 8. 上线前需要准备什么

1. **设备档案**：客户编号、机型、出厂编号、投产日期、保修截止。这是诊断的起点，
   没有档案系统只能靠文字猜机型。
2. **故障树与手册**：哪台机器、什么现象、对应哪个故障、怎么处置、要不要到场。
3. **备件清单**：物料号、适用机型、库存与货期。
4. **服务通报**：历史批次性问题的处理口径。
5. **历史工单**：至少近一年的服务记录，用于相似案例检索和工时预估。
6. **实时数据通道**（可选）：设备联网后的遥测或报警数据。没有也能用，
   系统会走"仅凭工单与手册"的路径并明确提示数据缺口。
7. **内网模型服务**（可选）：如果数据不允许出内网，可切换到内网 OpenAI 兼容模型，
   业务代码不需要改动。

---

## 9. 目前不支持的能力

- 不执行任何写操作：不改设备参数、不自动派工、不自动开票，结论只作为建议，
  对外内容由客服确认后发出。
- 不接语音与电话：需要客服把客户描述录入，或由呼叫中心系统对接。
- 不识别图片：铭牌照片、故障屏截图暂不能直接解析（文档型扫描件可以走 OCR）。
- 二线复核界面：`tech` 角色已保留，接手与打回"待确认"的操作界面尚未开发。
- 未与外部工单/CRM 系统打通：工单当前在平台内自建。
